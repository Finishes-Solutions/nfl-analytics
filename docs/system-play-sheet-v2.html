Three Tempos, One Client
  • Backfill — one-time, 2002→now, all season types (pre/reg/post), resumable via sync_state. Coverage probe writes coverage_map first so bulk requests only chase seasons that exist.
  • Nightly — timer: current-season games, box scores, season aggregates, standings, advanced; daily injury + roster snapshots; active-player sweep.
  • Game day — 1–15 min cadence for live-window games only (started <6h / starting <1h). Scores, box scores, plays tail, odds + props snapshots. Off-hours cost: one DB query, zero API calls.

Keyed tables: OPENJSON → MERGE. Snapshots: append-only. Overlapping runs are safe by construction.

Azure SQL · single database · single-digit GB · schema generated from tables.ts
Layer 1 — Raw Warehouse · 20 Tables

Every API field as a typed column + raw_json verbatim on every row. Nothing upstream sends is ever dropped — including fields the stale OpenAPI spec doesn't document. Two principals: nfl_ingest (writes, ingestion only) and nfl_readonly (DENY writes — every consumer).

Semantic layer · SQL views · computed, never stored · SHIPPED: fantasy scoring
Layer 2 — Views: Where Raw Stats Become Answers
  • Fantasy scoring (live) — v_player_fantasy_game / _season, v_dst_fantasy_game / _season, v_fantasy_points_allowed. Std / half / full PPR side by side, per-component breakdown, boom/bust profile (stdev, floor, ceiling), matchup difficulty by position.
  • Trends (next) — rolling 3/6-game averages vs season baseline, usage share, season-over-season deltas, regression flags.
  • Why views — one-line rule change (e.g. 6-pt passing TDs) rescores all 24 seasons instantly. The LLM and dashboard query this layer, so nobody re-derives math on the fly.

The Option Play — Fantasy Scoring Layer

v_player_fantasy_game → _season
Every Player, Every Game, 2002→

Three formats scored simultaneously with components exposed (pts_pass_yds, pts_rec_td…) so the UI can show the why. Season view adds totals, per-game, and the consistency profile totals hide:

fp_standardfp_half_pprfp_ppr stdevfloorceiling
fp = pass_yds×.04 + pass_td×4 − int×2 + rush_yds×.1 + rush_td×6 + rec_yds×.1 + rec_td×6 + rec×{0|.5|1} − fum_lost×2 + ret_td×6 + fg×3 + xp
v_dst_fantasy_game → _season · v_fantasy_points_allowed
Defenses — The Opponent-Row Trick

Your defense's stat line is the opponent's offensive row: their QB sacked = your sacks, their INTs thrown = your picks, their fumbles lost = your recoveries, their score = your points allowed (bracketed 10 → −4).

v_fantasy_points_allowed flips the join the other way: fantasy points each defense gives up per position per season — the "is this a good matchup" table, and the first feature of the future projection model.

Documented gaps · in the SQL header, not hidden

~95% fidelity, three known gaps: per-game FG distance bonuses (only season buckets exist upstream — flat 3/FG for now), two-point conversions (not a box-score field), DST safeties/blocked kicks (same). All three are recoverable later by parsing plays.text, which the warehouse is already capturing. None move rankings meaningfully.

Flags on the Field — Honest Caveats

🚩 Known risks before kickoff

  • Historical depth unverified until the probe runs. Advanced stats can't predate tracking (~2016); plays/team stats likely have their own floors. The backfill respects coverage_map, not the marketing claim.
  • OpenAPI spec is stale — schema is the union of spec + docs; raw_json catches what neither documents. Expect first-contact surprises.
  • Props are unrecoverable — every game-day cycle not run is archive lost forever.
  • Fantasy scoring is ~95% — flat FG scoring, no 2-pt conversions, no DST safeties/blocks, all recoverable from plays.text later. Rankings unaffected in practice.
  • "Live" has an upstream ceiling — measure changed-row rate before tightening cadence.
  • Player age/height/weight are current snapshots, not historical; no birthdate field exists.
  • Projections are a build, not an import — by scope choice. The archived props are the benchmark most hobby models never have.
